# 部署语音转写服务

当前是供个人设备使用的转写代理，使用现有硅基流动 API。代码可存 GitHub；真实 `.env`、供应商 key 和访问口令不提交，也不打包进 App。GitHub Pages 继续托管网页，转写服务单独部署。

## 部署平台配置

选择支持 Docker 和 HTTPS 的服务器或托管平台，将构建目录设为仓库的 `server`，使用其中的 Dockerfile。它只复制两个服务源文件，不复制 `.env`；用 Node.js 22、非 root 用户运行，不需要安装 Expo 或客户端依赖。

在平台的私密环境变量中配置：

- `SILICONFLOW_API_KEY`：原开发电脑 `.env` 中的硅基流动 key。
- `VOICE_ACCESS_TOKEN`：至少 24 字符的随机访问口令，与供应商 key 不同。
- `ALLOWED_ORIGINS`：`https://2441461233.github.io`，不要包含 `/moodtracker/` 路径。
- `ASR_MODEL` / `CLEANUP_MODEL`：可选，默认沿用 SenseVoiceSmall / DeepSeek-V4-Flash。
- `PORT`：服从平台分配的端口，Docker 默认 3100；`HOST` 保持 `0.0.0.0`。

平台必须允许至少 12 MB 请求体、至少 155 秒请求处理时间，关闭音频请求体日志和响应缓存。当前只运行一个实例：去重、并发和每分钟限流都存在单个进程内。平台如有自动休眠，首次转写可能等待唤醒；按需求选择运行方案。

无需 Docker、直接运行 Node 的主机使用 `node server/index.mjs`（仓库根目录）。生产环境由平台注入配置，不使用依赖本地 `.env` 文件的 `npm run voice:server`。

## 上线验证

1. 生成 HTTPS 服务域名，检查 `GET /health`。200 / `ready` 只表示本地必填配置存在，不验证 key 有效性或模型可用性。
2. 在「我的空间 → 语音与 AI 转写 → 连接转写服务」填写这个 HTTPS 地址和 `VOICE_ACCESS_TOKEN`，开启转写。这里不填写硅基流动 key。现有完整原生包无需为修改服务地址重新打包。
3. 用不含个人信息的短录音实际测试识别和整理，确认原文、整理文字、本机原声和失败重试。尚未完成这一步时，不宣称线上转写可用。

## 所有用户安装即用

当前个人口令不能作为公共 App 的内置共用口令。面向所有用户时，客户端可以预设公开服务地址；后端还需验证用户或受信设备身份，签发短期访问凭据，并以每个用户为单位实施配额、限流和费用控制。多实例部署需共享限流 / 去重存储。用户首次开启云端转写时明确说明录音会发送到该服务和供应商。

部署平台、用户身份方案和费用上限确定后再接入这一层。仓库提供的是部署材料，尚未据此创建线上主机，也未取得真实 key 或可用 HTTPS 地址。
