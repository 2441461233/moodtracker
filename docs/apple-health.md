# Apple 健康心境接入的边界

此功能连接 HealthKit 的 `HKStateOfMind`，不是正念分钟 `mindfulSession`，也不是诊断量表。用户不开启健康功能时，原有日记与统计完全独立。

## 用户明确控制的两个方向

**读取**：在设置面板中主动点击，选择近 30 / 90 / 365 天，最多获取最近 200 条。保留来源、原始愉悦度和 `momentaryEmotion` / `dailyMood` 的区别，不把全天整体心情伪装成本地即时记录，也不混入统计。

**写入**：先选择范围，再确认条数及用途，最后申请写权限。写入时间、心情和可明确对应的活动。无自动后台写入、后台观察者或定时同步。

苹果不向 App 透露读取被拒绝的状态。授权请求完成只代表面板流程结束；空查询可能没有记录，也可能没有读取权限。写权限状态单独显示，不用它推断读权限。

## 映射不是原始数据替代

| 本地心情 | 写入的愉悦度 |
| -------- | ------------ |
| 很开心   | +1           |
| 还不错   | +0.5         |
| 还好     | 0            |
| 有点烦   | −0.5         |
| 很难过   | −1           |

映射沿用日记五档顺序，只是近似整理，不推断疾病或具体 Apple 感受标签。所有写入均为“当下情绪”。工作、运动、朋友、家人、伴侣、学习、兴趣、旅行、健康等有直接对应的活动才写入；睡眠等无直接对应的标签保留本地。文字笔记、称呼、任意自定义字段不进入 HealthKit。

## 去重、修改与失败

- 稳定的 `moodtracker:<本地编号>` 作为 `HKMetadataKeySyncIdentifier`，使用递增版本更新同一条数据。
- 写入前将待处理版本保存到独立本地账本 `moodtracker_health_export_v1`；确认成功后才标记完成。保存失败不谎报成功，重试使用同一版本。
- 未变化且已确认的条目跳过；笔记不参与对比。修改心情、时间或对应活动后，用户再次手动写入才更新。
- 账本损坏时停止写入，不静默清零或重置版本；日记原件不受影响。
- 版本使用本地时钟与上次版本递增值的较大值。设备时间回退、另一个设备写入更高版本仍可能产生冲突，不能宣称具备跨设备实时一致性。
- 用户在健康中删除已发送的记录后，账本不会自动探测或重新补回。删除本地记录也不删除健康副本；需要在健康中单独管理。

## 数据保管

从 Apple 健康读取的样本仅保留在当前打开页面的内存中，关闭面板或 App 进入非活动状态时清除，不存入 AsyncStorage、不加入 JSON / CSV、不交给服务器或 AI。

同步账本仅包含本地日记写入所需的版本、内容指纹及确认状态，不保存文字笔记或从健康读取的样本。账本不参与日记导出，因此新设备导入备份不等于恢复一份完整同步状态；用户需要重新确认写入。

本应用没有自建云端日记、广告或追踪系统。用户主动写入 Apple 健康后，健康数据的 iCloud / Apple Watch 同步由 Apple 系统和用户设置管理，不能把它描述为“绝不离开设备”。普通本地日记和导出文件仍没有单独加密，请保护设备及备份访问权限。

原生编译、真实授权与健康 App 可见性是不同的验证层次。仅 JS 测试通过、网页已部署、Swift 语法检查通过，都不构成已完成真机健康接入的证据。见 [iOS 发布与真机验收](ios-release.md)。
