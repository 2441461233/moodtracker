# Apple 健康心境自动同步的边界

本文描述 **2.1.2 当前修订的设计与验收边界**。提交前本地 `npm run verify` 已通过 172 项回归及 19 项网页测试；隔离合成夹具已验证统一时间线、来源筛选、分页、两种心境独立回顾，以及待读取 / 权限未知 / 断开后移除健康展示。夹具不是真实 HealthKit，未测真机、大字体或真实 VoiceOver。截至 2026-09-03 08:22 UTC，2.1.2（6）已完成原生构建、下载及严格 IPA 验签，尚未上传或分发；独立原生 CI 仍在进行中，首次网页 CI 的短定时器测试竞态已修正并本地 172 / 172 通过，网页复跑待推送。历史 2.1.1（5）已于 07:30 UTC 核实在既有内部 TestFlight 组可用，不能把该历史证据当作 2.1.2 已上线。精确状态见 [iOS 发布与真机验收](ios-release.md)。

此功能连接 HealthKit 的 `HKStateOfMind`，不是正念分钟 `mindfulSession`，也不是诊断量表。仅限 iOS 18+ 的完整原生包；网页版、Android 和 Expo Go 不支持。用户不开启连接时，原有日记与统计完全独立。

## 一次明确开启，之后自动响应

尚未开启连接的用户在“我的”中阅读范围和隐私说明，再点击“开启自动同步”，这一步才请求心境读取和写入权限。已在 2.1.1 开启的连接偏好与系统权限继续沿用，不因 2.1.2 增加展示入口而无故再次开启或授权；启动、保存日记、重试计时及普通页面切换均不反复弹授权。本次没有扩大健康类型、365 天时间范围或 5,000 条读取上限。

- **本地 → Apple 健康**：首次开启会处理最近 365 天的现有本地记录。之后日记成功持久化后的新增或心情、时间、可对应活动修改，由全局同步协调器触发写入；只改文字笔记不会触发健康更新。过期范围外记录不会新增到健康。
- **Apple 健康 → 只读展示**：读取近 365 天、最多最近 5,000 条，保留来源、时间、原始愉悦度及 `momentaryEmotion` / `dailyMood`。前台内存中的统一时间线把健康心境接入今日每日列表、月历 / 年像素、选中日期与独立健康回顾；不是仅显示最新三条摘要。不复制为本地日记，不导出或写回 Apple 样本。
- **重新回到前台**：会自动检查连接、补齐本地写入并重新读取健康心境，无需每次点“同步”。“立即重试”只作为故障恢复入口，不是正常使用步骤。

Apple 不向 App 透露读取被拒绝的状态。授权请求完成只代表系统面板流程结束；空查询可能没有记录，也可能没有读取权限。UI 显示“未读到记录”，不会称为读取授权成功。写权限状态单独显示；拒绝写入会暂停写入并提示用户去系统健康权限中处理，不靠自动重试反复申请授权。

## 自动不等于后台秒级实时

原生 `HKObserverQuery` 观察心境新增、修改或删除引起的变化，事件只包含变化原因、内存中的修订计数及安全错误码，**不携带健康样本、笔记或来源资料**。已开启连接时注册 HealthKit Background Delivery；系统回调被确认接收后，由前台协调器重新查询数据。[Apple Observer Query](https://developer.apple.com/documentation/healthkit/hkobserverquery)

当前实现的后台唤醒仅处理无数据的变更通知，不在后台保留或查询样本；数据在下次前台读取。前台运行时响应事件，回到 App 时也会补齐。Apple 控制通知频率、系统资源和后台调度，因此不承诺秒级、持续不间断或跨设备实时一致；用户彻底关闭 App 后也不能承诺持续运行。后台通知暂不可用时，前台自动同步及回到 App 补齐仍可工作。[Apple Background Delivery](<https://developer.apple.com/documentation/healthkit/hkhealthstore/enablebackgrounddelivery(for:frequency:withcompletion:)>)

原生包须带 `com.apple.developer.healthkit.background-delivery=true`。现有 App Store provisioning profile `JHW9QHZK8M` 和历史 2.1.1（5）签名包均已核验包含此权限；2.1.2 未扩大权限，但包含原生查询身份与用途说明修订，不能仅推送 JS。当前 2.1.2（6）已完整重新构建，最终 IPA 的实际签名与内嵌 profile 均已核验 HealthKit / Background Delivery 为 `true`。签名和模拟器构建不验证后台通知；该行为仍必须在真实 iPhone 验收。[Apple Background Delivery entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.healthkit.background-delivery)

## 统一时间线、去重和回顾口径

- `TimelineRecord` 是前台视图模型，明确区分 `local` 与 `apple`。本地记录继续可编辑；Apple 记录标为只读并保留原始来源、类型、时间和愉悦度，不交给本地保存或写入健康的流程。
- 同一健康 UUID 只显示一次。仅当样本确由本 App 写入、bundle identifier 精确匹配、且系统同步标识提取的稳定本地 ID 对应现存日记时，才隐藏该健康副本，避免同一记录重复展示和计数。不是按相近时间、愉悦度或来源名称猜测去重。
- 对应本地记录不存在的本 App 自写样本仍以 Apple 只读记录展示；外部来源即便内容相同也保留。没有同步 ID 的旧样本不被猜测移除。隐藏副本只作用于视图，不删除任一侧数据。
- 日历默认“全部”来源，可切换“本地 / Apple 健康”，同时作用于月历、年像素、每日列表与期间统计。关键词按当前来源跨日期搜索，心情筛选只控制列表，均不改变日历颜色及期间统计。
- Apple 原始愉悦度用 `valence × 2 + 3` 映射到 1–5，仅作五档近似色彩与统一回顾，原值不被覆盖或反向写回。当前来源中某日有 `dailyMood` 时取整体心情均值，否则取 `momentaryEmotion` 均值；期间平均对有记录的日子等权。
- 独立 Apple 健康回顾按两种 kind 分别统计原始愉悦度样本均值，不将一天整体心情与当下情绪混成一个均值。本地趋势、心情分布、活动关联和连续天数仍只根据本地日记，不混入 Apple 样本。
- 查询未完成、权限未知、超出 365 天或达到 5,000 条上限时均显示范围提示；未读取部分不是“没有记录”，空白和缺失不能当作零分。

## 映射不是原始数据替代

| 本地心情 | 写入的愉悦度 |
| -------- | ------------ |
| 很开心   | +1           |
| 还不错   | +0.5         |
| 还好     | 0            |
| 有点烦   | −0.5         |
| 很难过   | −1           |

映射沿用日记五档顺序，只是近似整理，不推断疾病或具体 Apple 感受标签。所有本地写入均为“当下情绪”。工作、运动、朋友、家人、伴侣、学习、兴趣、旅行、健康等有直接对应的活动才写入；睡眠等无直接对应的标签保留本地。文字笔记、称呼和任意自定义字段不进入 HealthKit。

## 去重、修改、停止与失败

- 稳定的 `moodtracker:<本地编号>` 作为 `HKMetadataKeySyncIdentifier`，使用递增版本更新同一条数据。
- 写入前将待处理版本保存到独立本地账本 `moodtracker_health_export_v1`；确认成功后才标记完成。失败不谎报成功，重试使用同一版本；未变化且已确认的条目跳过。
- 全局协调器串行处理持久化后的最新日记快照，合并重复变更事件。自身健康写入产生的通知不会造成无限重复写入，已确认的账本条目会跳过。
- 瞬时查询、写入或受保护数据暂不可用等可重试错误，使用 **5 / 15 / 45 秒**的有界自动重试。达到本轮上限后停止定时重试并显示安全错误信息；权限拒绝不会自动再次弹出授权。回到前台、新持久化变化或用户明确重试可开始新的处理机会。
- 错误按白名单安全码转为固定说明，不把原始系统错误描述、健康记录或笔记带入日志和 UI。账本损坏时停止写入，不静默清零或重置版本，日记原件不受影响。
- 关闭自动同步会取消后续排队工作、停用观察与后台通知并清空读取内存；不会删除日记或健康记录。已经交给系统并完成的单次写入不作为删除操作撤回。
- 在健康中删除已发送记录后，账本不会自动补回；删除本地记录也不删除健康副本。Apple 侧编辑只刷新只读显示，不覆盖本地日记；不是跨方向自动删除的镜像。
- 版本使用本地时钟与上次版本递增值的较大值。设备时间回退、另一台设备写入更高版本仍可能产生冲突，不能宣称跨设备强一致。

## 数据保管

从 Apple 健康读取的样本及统一时间线派生结果仅保留在前台运行内存中。关闭设置面板后，今日、日历和独立健康回顾仍可使用同一份前台快照；**关闭连接或 App 进入非活动 / 后台状态时清除**，回到前台重新查询。样本不存入 AsyncStorage，不复制进 `mood_entries`，不加入 JSON / CSV，不交给服务器或 AI。读取用途说明对应这些按日期展示与独立回顾用途，写入用途仍只涵盖本地心情 / 时间 / 对应活动，不包括文字笔记。

同步账本仅包含本地日记写入所需的版本、内容指纹及确认状态；原生保存连接是否开启的偏好，以便下次启动恢复观察。两者均不保存文字笔记或从健康读取的样本。账本不参与日记导出，因此新设备导入备份不等于恢复完整同步状态；新设备仍需明确开启和授权。

本应用没有自建云端日记、广告或追踪系统。用户开启后写入 Apple 健康的心情，其 iCloud / Apple Watch 同步由 Apple 系统和用户设置管理，不能描述为“绝不离开设备”。文字笔记不传入健康；普通本地日记和导出文件仍没有单独加密，请保护设备及备份访问权限。

原生编译、签名 entitlement、真实授权、自动同步和健康 App 可见性是不同验证层次。仅 JS 测试、网页部署或 Swift 编译成功，都不构成已完成真机健康自动同步的证据。
