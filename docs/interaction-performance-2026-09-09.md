# 交互性能优化 · 2026-09-09

本轮修改记录表单、全局状态订阅、页面统计、存储读取和装饰动画。没有添加运行时依赖，也没有改变日记存储格式。

## 处理的问题

- **全局状态带动无关页面重绘**：拆分日记数据、操作、弹窗、时钟、提示订阅，并稳定操作函数及健康状态对象。导航、提示和弹窗分别渲染；打开记录不再更新时间并刷新所有页面。
- **笔记逐字刷新整张表单**：文本和字数独立更新，完整草稿同步写入 ref。切回上一步再进入、立即保存和失败重试均保留当前文字，没有防抖延迟。
- **切步高度突变和滚动残留**：记录弹窗使用受屏幕和安全区约束的固定高度，内容内部滚动；步骤改变时在布局阶段归零滚动位置。保存操作仍固定在底部，保留键盘避让和收键盘入口。
- **渐变需要额外测量再重绘**：2.1.8 曾移除测量，但随后发现 iOS 按钮背景只绘制一部分。2.1.9 恢复原生实际尺寸测量并隔离背景，尺寸未变时不更新状态；网页继续直接铺满。详见 [按钮回归修复](native-button-regression-2026-09-09.md)。
- **不可见内容占用工作量**：原生非当前标签页启用 freezeOnBlur；弹窗显示或 App 进入后台时暂停背景光斑动画；常驻动画不占交互任务句柄。
- **重复计算与读取**：缓存首页、记录页及洞察统计；搜索使用延后渲染和列表 memo，优先响应输入。定时器仅在日期/小时变化时更新页面时钟，表单打开时独立读取准确时间。
- **无变化读取重建整个日记数组**：每次仍在原有协调锁内读取最新存储原文；原文未变时复用只读快照，变化时重新解析校验。只有写入成功后才更新缓存，保留跨实例冲突、失败重试和损坏数据保护。

## 渲染对照

使用同一隔离浏览器夹具运行修改前后的真实 React Provider / EntryComposer。服务替换为内存适配器，计数由测试打包时注入，不进入生产包。

| 操作                                            | 修改前                                              | 修改后                                    |
| ----------------------------------------------- | --------------------------------------------------- | ----------------------------------------- |
| 弹出提示                                        | 日记、操作、时钟、弹窗订阅一起重绘，回归断言失败    | 仅提示更新，断言通过                      |
| 打开/关闭记录、重新读取未变化的数据             | 共享状态会传播无关更新                              | 日记与操作订阅无额外重绘，断言通过        |
| 逐字输入 `abcdefghijklmnopqrstuvwxyz0123456789` | 输入触发 36 次整表单重绘；测量窗口另有 1 次时钟更新 | 整表单额外重绘 0 次，文本和字数仍实时更新 |

这是浏览器中 React 渲染次数对照，不能解释为 iPhone 帧率或真实设备耗时提升比例。

## 原生验证边界

本机缺少 Xcode / simctl，尚未实测 iPhone 中文输入法联想、键盘升降、系统时间滚轮、原生标签冻结恢复和真实帧率。Hermes 导出只验证 JavaScript 与资源可打包，不能替代真机验收。
