# 2.1.9 原生按钮修复与验收

用户在 2.1.8 的 iPhone 截图中指出：「继续」按钮只有上半部渐变，下半部发白，白色文字失去对比。此前的网页点验、Hermes 导出与原生编译没有验证原生屏幕的实际绘制，这次验收缺口由运行中的 iOS UI 测试补足。

## 修复

共享 Gradient 把 SVG 放入独立的绝对定位背景层，按钮的图标和文字继续参与正常排版。原生端使用外层 View 测量的完整宽高，避免依赖带内边距的 Fabric / SVG 百分比绘制；首帧测量前提供底色，保证按钮文字可见。尺寸相同则复用状态，不引入重复布局重绘。网页继续直接铺满背景，笔记独立更新等性能优化保留。

该修复覆盖使用同一组件的「继续」「保存」「保存修改」及其他主按钮。

## 回归方法

- 生产组件测试：首帧可见底色、背景与文字分层、原生数值宽高、窗口尺寸变化、相同尺寸不重复更新、网页立即绘制。
- 将相同回归测试作用于 2.1.8 的旧组件，3 项均失败；修复后 3 项通过。测试能拒绝这次引入问题的实现。
- iOS XCTest 使用真实 Release App，覆盖浅色 / 深色、未选心情禁用、选择后继续、带上一步的继续、键盘打开后的保存、笔记往返保留及最终进入记录列表。
- 原生截图除了人工检查，还对按钮上下四分之一位置采样：两处都必须保留紫色渐变。只检查 accessibilityLabel 或编译成功无法代替此检查。
- 通过 [XCTest 截图附件](https://developer.apple.com/documentation/xctest/adding-attachments-to-tests-activities-and-issues) 保存每个关键步骤，供下载和复核。
- 网页发布新增同一提交的原生 UI 验收门槛，原生工作流失败或超时会停止部署。
