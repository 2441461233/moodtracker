# 录音结束闪退排查（2026-09-10）

用户反馈：第三步点击「结束录音」后立刻退出 App。最初 Apple 官方 API 查询无反馈；用户再次提交后，已取得这次 2.1.10（16）/ iOS 26.6.1 的真机日志。终止类型为 `EXC_CRASH (SIGABRT)`，崩溃线程在 React `ObjCTurboModule::performVoidMethodInvocation` 异常传播路径中退出，主线程同时在卸载原生视图。日志没有保留具体异常文本，不能仅靠该通用调用栈认定是某一个音频函数；也不能把下面的生命周期缺陷直接当作这次闪退的唯一原因。原始设备报告仅在本机诊断目录保留，不提交公共仓库。

## 已确认并修复

- 回听组件在 React render 中通过 `useAudioPlayer(null)` 创建原生播放器。初始化错误会越过组件自身的异步错误处理，影响整个记录界面。改为确认本机录音文件后，在可捕获错误的异步流程中创建播放器；失败时提示并保留原声导出和记录保存。
- Expo 的 `useAudioPlayer` 内部释放 effect 注册在组件清理 effect 之前，组件卸载时仍调用 `player.pause()`，可能访问已释放原生对象。改为同一 effect 持有播放器、移除监听、停止再释放；切换文字、关闭记录和保存均走同一顺序。
- 等待音频模式切换或播放定位时离开页面，异步恢复会访问旧播放器。增加实例一致性检查，退出后不再恢复播放。
- 录音结束原流程先解锁界面并创建播放器，再不等待地切换音频模式。改为先保留原声、完成录音到播放模式的切换，再展示回听和解锁界面。所有音频模式切换串行执行，明确传入完整的前台模式。
